# Implementation and setup status

Checked 4 November 2026 (Philippine time).

- The protected Vercel staging deployment is connected to the dedicated Supabase PostgreSQL project through the transaction pooler. The project is linked locally and its Node.js version is set to 24. DATABASE_URL is configured for preview and production.
- A synthetic wholesale inquiry was submitted to the protected deployment and verified in the database with its product and attribution. Staff login, viewing the inquiry and saving a status and internal note were verified against the deployed application. The synthetic inquiry was then deleted.
- Supabase has the private schema migration and the four-product seed. Its security advisor previously returned no findings. Production and preview currently use the same database; keep tests synthetic and avoid altering real inquiries.
- Staff credentials were regenerated after a cleanup policy blocked removal of temporary test files. The current credentials are in ignored `web/.env.admin-credentials`, and their hash and session secret are stored in Vercel. Prior protected deployments can retain earlier environment values. The temporary Windows files `crunchify-login-test-form.txt` and `crunchify-login-test-cookies.txt` require user removal; the first contains the previous password and the second a prior session cookie. No secrets are committed.
- The private GitHub repository is `Lester0961/crunchify-trial`, with an initial commit on `codex/crunchify-trial`. Vercel reports it as connected. Client source archives, wireframes, environment files, dependencies and build output are ignored; the optimized product photos and logo needed by the application are included in the private repository.
- The user selected Brevo and authorized their own verified Gmail address for temporary public notifications and sender identity. In public production and protected preview, synthetic confirmation and notification messages arrived; the synthetic database records were removed. The production notification landed in Gmail Spam, and Brevo rewrote the Gmail sender to a Brevo sending address. Company-approved authenticated sender/domain and notification recipient remain missing. The public form accepts a database save when emails fail and informs the visitor; staff must monitor and retry failures.
- `npm run build`, `npm run lint`, production dependency audit and browser smoke checks passed. Browser checks covered widths of 320, 390, 768 and 1440 pixels, mobile navigation, category filtering, product preselection, invalid input and the unauthenticated admin redirect. One local mobile Lighthouse run measured performance 98, accessibility 100, best practices 100 and SEO 63 (noindex enabled). Email receipts were verified in both preview and production, including a recovery retry. No screen-reader test, real-device test, Docker build or actual VPS migration has been verified.
